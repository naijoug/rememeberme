# Native architecture

`Apps/macOS` and `Apps/iOS` own platform application lifecycles. `RememberMeUI` owns shared native views and a MainActor presentation model. `RememberMeCore` owns value models, codecs, restore planning, review-v1 rules and the actor-isolated repository. These packages do not import browser storage or Vue/WXT code.

The repository owns a private Core Data context and SQLite coordinator. Each mutation runs on the context queue, commits to the persistent store, then returns domain values. Managed objects never cross actor/UI boundaries. A failed save rolls back and resets the context; UI acknowledgements follow committed results.

Store models `RememberMeStore-v1` through `RememberMeStore-v4` are retained in source. V1 is the foundation model; V2 adds indexed `createdAt`/`reviewDueAt` columns and quota admissions; V3 adds durable captures; V4 adds logical sequence/dependency metadata and sync records. Known older stores migrate to a separate database and get a coherent pre-upgrade recovery copy before replacement. Unknown versions fail without deleting the original. Migration tests use real SQLite data.

| Entity | Ownership |
| --- | --- |
| Partition | Owner-scoped active generation and monotonic local revision |
| Entry | Generation-scoped domain summary, optional Double count and indexed search/sort fields |
| Encounter | Independently stored, ordered history payload; indexed by owner/generation/entry/position |
| Operation | Generation-scoped logical operation identity, sequence, causal/observed server metadata and payload |
| SyncRecord | Generation-scoped configuration, remote base, frozen wire item, history marker/checkpoint and conflict payloads |
| Source | Published migration source digests |
| Batch | Durable candidate generation, base revision, progress and publication state |
| ReviewAdmission | Owner/local-date admissions; committed with review events and retained across generation changes |
| Capture | Owner-scoped pending/confirmed/dismissed draft payload and stable confirmation request digest |

Definitions, review values/events, source aliases and permissive optional legacy fields are encoded in entry summaries. Encounter history is stored separately so list/detail-summary fetches do not load it. Review queues use indexed due/creation times and local-date admission checks. Separate review-event paging/query storage remains unfinished; sync protocol state now lives in SyncRecord.

An import candidate copies the current generation, including internal sync state, and applies chunks to its own rows. Normal queries and pending-operation reads only use the partition's active pointer. Publication checks the base revision and commits the pointer and published batch status in one save. Copy chunks save their cursor and cloned rows together, so failure/restart does not repeat rows. Staging uses an immutable private plan with a digest and keeps operation IDs through resume; old JSON plan files and older ready/cancelled receipts remain supported. Import receipt evolution is independent from the V4 sync model upgrade. The model must never recover a load failure by deleting a user's store.

Large plans are encoded/decoded per entry as compact JSON lines, with a small header preserving operation order; encoding an entire duplicated history graph is avoided. The active store remains queryable between bounded copy/stage/cleanup chunks. Revision changes block stale tasks rather than rebase them implicitly. Startup exposes jobs but does not auto-publish. Discard marks the batch cancelled before bounded cleanup; interrupted cleanup remains discoverable. After successful publication, pruning recalculates protected generations in every transaction and retains active, latest recovery and in-flight data. Legacy receipts without enough recovery provenance prevent unsafe pruning.

Anonymous and account partitions are isolated in local tests. Account ownership and sync integration are now explicit application paths. `AccountVocabularyModel` first performs a read-only cloud pull with sending paused. Ownership choices become a frozen `bindAnonymous` import plan; publication rechecks account generation/revision, identity/epoch and anonymous generation/revision, and saves mapping receipts with the account pointer in one store transaction. The anonymous revision is part of that optimistic transaction and its data stays available. Shared-source migration preserves the original seed and subsequent logical operations; unrelated local entries create one current snapshot instead of replaying their anonymous outbox. Association preserves the cloud count, while explicit field replacement/new lifecycles require separate choices. Public backups omit internal operation/checkpoint/ownership receipts; they preserve ordered history and optional ordering/source provenance.

See [contracts](../../../contracts/README.md), [behavior](behavior.md) and [testing](testing.md). Server envelopes and Keychain/sync implementation must pass the plan's stage-four gate before account features are enabled.

`LocalWordNet` reads bounded Bundle shards off the main thread, using the extension's hash and verified morphology ordering. `LookupService` uses an ephemeral URLSession without cookie/credential storage, independent deadlines/caches and cancellation-aware request coalescing. Draft request IDs protect newer selections from late results. Native resource references use the extension source assets directly; a pinned SHA-256 manifest checks source and built copies.

`ReminderSettings` schedules nonrepeating UserNotifications for up to seven upcoming local dates. The pure date planner handles DST; the platform layer checks authorization, rebuilds requests from the local review queue, and cancels obsolete requests with generation-specific identifiers. UI-test store sessions skip notification requests and scheduling. No background task is required or promised for precise delivery. Actual system delivery/tap behavior remains platform acceptance work.

The Share Extension writes one immutable JSON file per capture ID in the App Group inbox. A synchronized temporary file is published via an exclusive hard link, so concurrent writers cannot overwrite stable IDs. The main app drains to its private store before removing the shared file. Confirmed/dismissed IDs persist to protect against re-delivery; confirmation commits entry/outbox/state together and creates no encounter. Shared source text/URL becomes a separate `captureOrigin` field after confirmation and is rendered literally. The extension never writes vocabulary directly. Group signing and real host behavior still require device acceptance.

`NativeSession` owns per-origin credentials and a generation lease. `KeychainCredentialVault` uses synchronous Security framework operations within the actor turn, preventing reentrancy between checking a lease and committing/removing credentials. Shared refresh tasks validate returned owner/device and save rotated credentials once; if Keychain persistence fails after server rotation, the completed refresh stays available for a local retry. Logout/account replacement invalidates pending network results.

`APIHTTPClient` scopes endpoints to the configured origin; its URLSession transport blocks HTTP redirects, does not use cookie/credential storage, cancels oversized/stalled tasks and exposes bounded structured error results. `AuthenticatedAPIClient` retries a rejected access token through one refresh and checks the original account lease before returning data.

`NativeSyncAPI` validates state/history envelopes and submits saved wire bytes with their epoch. History scans bind the base entry version and use immutable ID cursors; retained positions reconstruct original order after the complete scan. Explicit legacy merge selects stable timestamp/position ordering. `SyncCoordinator` coalesces finite foreground flights, checks enabled account identity around network calls, saves cursors with state/events, and persists retries/conflicts. Its separate read-only mode prepares ownership previews without sending queues. Conditional bases account for duplicate predecessor events without adopting unseen concurrent versions. Partially acknowledged merge/restore fields and pending review answers are not applied twice. A changed epoch pauses sending until explicit recovery publication; hosted restore acceptance remains unfinished. See [sync core evidence](verification/2026-10-09-sync-core.md) and [account integration](verification/2026-10-09-account-ownership.md).

`AccountVocabularyPool` shares one account-selection/controller per store URL across windows; `RepositoryPool` shares one actor per URL/owner. Selection invalidates old presentation queries, drafts/export buffers and import tasks, then refreshes/reminds from the new partition. View actions carry their original owner so a stale editor cannot write into another account. Settings exposes read-only opening, ownership preview, explicit sync enablement and confirmed conflict actions. Foreground/local-mutation signals request bounded sync. Connection replacement cancels work, pauses the old account configuration and selects anonymous vocabulary. Basic cloud-value/separate-copy actions exist; source-consent enrichment and hosted restore acceptance remain unfinished; account backup merge is now connected. Tests inject synthetic browser/session/API services and avoid system notifications.

`ServerSnapshotLoader` independently downloads fixed-boundary state plus version-bound history for recovery previews. It validates unique lifecycle/position identities, reconstructs retained order and rechecks account/epoch/preferences after reading. `EpochRecoveryPreview` converts confirmed cloud/local/separate-lifecycle choices into a `reconcileEpoch` candidate with new bases/checkpoint/requests; it does not copy the old outbox. Streamed item records carry remote bases with verified identities/count/hash. Missing words/local tombstones and immutable event conflicts remain explicit. Online validation is scoped to account/device/epoch/preferences and expires after 60 seconds; both confirmation and resumed UI jobs recheck before publication. Old generation and requests remain the recovery point. The pointer, configuration, conflicts and current review quota switch in one save, with sync still disabled. Current server admission IDs and local IDs are counted as a union; historical answers are never replayed. See [epoch recovery evidence](verification/2026-10-09-epoch-recovery.md). Local HTTP results do not replace hosted database restore or signed-device acceptance.

`AppleWebAuthenticator` retains ASWebAuthenticationSession and its continuation, supplies a current native presentation anchor, requests an ephemeral browser session and handles task cancellation. `AccountConnectionModel` permits real requests only from explicit normal-session Settings interaction; disposable UI-store sessions do not read persistent account settings or contact Keychain/network unless an injected test explicitly opts in. Mock tests never open the real system browser.

`AccountRestorePreview` combines current server state with local pending overlays and a parsed backup. Default choices retain current fields; chosen subsets become fresh conditional snapshots, history-only imports or explicit new lifecycles. Incoming requests/checkpoints are rejected, affected pending fields cannot be overwritten, and unrelated current queues are copied into the candidate. Frozen provenance records expected lifecycle versions and relevant spelling/ID sets; confirmation/resume reloads cloud state and requires a recent validation before atomically activating the candidate. Offline cached preview cannot publish. Current tombstones and immutable history are protected, and sync stays paused. See [account backup evidence](verification/2026-10-09-account-backup.md). Lookup coalescing additionally checks cancellation at reply/cache return boundaries; cancellation tests gate the provider until subscriptions are registered.

## Source privacy and large outboxes

`SourcePrivacy.swift` owns bounded explicit source backfill, local source-request eligibility and durable source-removal receipts. Logical operations freeze per-device consent and account source revision at enqueue time; encoded requests retain exact bytes on retry. The coordinator checks source eligibility before submit. Clearing pauses sending and persists the request before I/O, then accepts only its matching revision reply. A lost reply can be retried across restart. Old source requests stay conflicted rather than being silently re-encoded. Local encounter text and backups are retained.

The backend checks account consent/source revision at validation and rechecks them inside the guarded SQLite transaction. Migration 0005 adds account source revisions and idempotent removal receipts. Clearing atomically removes source columns and disables both flags; a previously committed operation receipt can still be acknowledged but never executes again. Snapshot/recovery publication rechecks source revision so clearing during a preview invalidates it.

Outbox selection reads pending logical operations in batches of 50, resolves dependencies by ID, and filters wire records in the store. Sync status uses database counts rather than decoding every payload. The synthetic sync benchmark measures request freeze/retry/reopen and status latency; it does not simulate hosted throughput.

## Connected Chinese translation

Account connection injects an authenticated backend Chinese provider into the
shared lookup actor. It sends only the selected word and `zh-CN`; credentials stay
in Keychain and Hermes keys remain server-side. Cache namespaces include backend
origin and account. Provider changes invalidate old in-flight results; packaged
English lookup remains independent. Connected failures remain explicit and do
not silently switch providers. Disconnected lookup retains MyMemory. Definitions
accept both `hermes` and historical `mymemory`, with no rewrite of old histories.
The default API runtime is Node/SQLite. The 2026-10-14 host record confirms its
Tencent Lighthouse deployment, live isolated Hermes, server-side trusted HTTPS
and configured GitHub credentials. Public access remains blocked by filing in
that record; completed hosted OAuth and signed/installed-client synchronization
remain unaccepted. See [current deployment status](../../../backend/docs/tencent-deployment.md).
