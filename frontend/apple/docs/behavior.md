# Native client behavior

This describes the current implementation foundation. The full [Apple plan](../../../docs/apple-clients-implementation-plan.md) remains the release scope.

- Both native apps start with an empty anonymous local vocabulary. No login is required. The app does not inspect Chrome profiles or extension storage.
- Manual adding saves a word and optional literal meaning with an unknown count. Opening a detail does not increment it. Record once forgotten appends one event and increments count, even with an empty definition. Reusing an event ID is idempotent only for identical content.
- Reset makes count zero while retaining history. Delete requires explicit Cancel/Delete confirmation and retains a local tombstone; cancellation leaves the word intact.
- Search and count/updated-time sorting query the local store. The UI displays 100 words at a time with Show more words, and 50 history records at a time with Show more records. List/detail queries do not load full encounter history. Native font scaling follows SwiftUI; VoiceOver/device accessibility acceptance has not been performed.
- Import extension snapshot preserves source identity and skips a previously imported byte-identical file. A differently formatted file is a different source and can conflict by word. The compatibility merge entrypoint explicitly warns that each new import adds count and history again. Anonymous cross-source conflicts offer explicit skip, history association, count/definition selection or a separate lifecycle. Association preserves count and distinct event IDs; aliases retain the source mapping. Multiple matching entries require a target choice. Applying source choices only rebuilds the preview; Import publishes. Explicitly skipped words are recorded as handled for that source. Account ownership remains a separate flow.
- Import parses and previews before saving. Candidate writes are durable but invisible. Existing-data preparation and entry staging show progress and support cancellation. Publication checks vocabulary revision and switches the active generation atomically; failure/cancellation before publication leaves the active vocabulary intact. Interrupted imports lists saved jobs after relaunch and offers Resume, Discard import or Finish cleanup. Resume uses the original plan and IDs without applying a merge twice. Changed vocabulary requires discarding and re-previewing the source; damaged plans never publish. No interrupted job is resumed automatically.
- The detail displays saved definitions, examples and literal context with complete date/time. Old timestamps outside the supported display range are labeled without altering exported values. HTTP(S) history URLs can open in the default handler; file/javascript/etc. URLs display as text.
- Add/Edit supports explicit paste, manual meaning and notes, and independent English/Chinese lookup results and errors. WordNet exact/base-form hits stay local; English misses use Free Dictionary API, Chinese uses a separate seven-day success cache before MyMemory. Each request sends only the single word. No network request occurs merely from opening an entry. Refresh does not persist until Save, and editing does not rewrite historical definition snapshots. Both providers may fail while manual/empty-definition saving remains available.
- Export complete backup retains independent definitions, notes, count/history, review state/events, tombstones and source IDs. Legacy export first explains losses: unknown count becomes zero; new types, notes, current-only definitions, reviews and tombstones are omitted. Both exports may include sensitive contexts/URLs. Anonymous merge restore keeps current values by default and permits separate count, definition, notes, review schedule, spelling, type, capture source and deletion-state choices; immutable event conflicts and tombstones cannot be overwritten. Replace is limited to anonymous local vocabulary and confirms that existing data will be replaced. Native file picker/export sheet behavior still needs broader platform acceptance.
- Learn words is a direct toolbar action (Command-Shift-R on Mac); Options → Today’s review and reminder routing open the same learning view. Cards hide saved meanings/examples and notes until revealed, then offer Forgot/Fuzzy/Remembered (Space to reveal, 1/2/3 to answer). The view shows the full due count even when more than 50 cards are due, the remaining daily new-word allowance, and this session’s committed answer totals by result plus the last answer’s next review time. Session totals reset on closing; persisted review state and daily admission limits do not. Failed or conflicting answers do not increment session totals. Loading failure offers Reload words instead of reporting completion. Changed cards, including edits to the same word from another window, hide the answer again. Foreground entry refreshes the queue. Review-v1 changes intervals independently of forgotten count and encounter history. New words enter at most 20 per local date, persisted through restart; already studied words appear only when due, with due words first. Concurrent/duplicate answers use reviewVersion and event ID checks. Imported review history is not replayed.
- Settings persist System/Light/Dark appearance separately from vocabulary. Reminders default off, request system permission only when enabled, and schedule at most seven upcoming local-time notices from known vocabulary. Completed review/store changes, reopening/foreground and disabling trigger rescheduling/cancellation. Notification text does not claim an exact due count. System delivery, focus-mode effects and notification routing in real devices remain unverified; tests do not request notifications.
- Cloud sync is off for anonymous vocabulary. Settings can open a connected account through read-only pulls, then enable its queue explicitly. Anonymous data enters an account only through confirmed ownership choices; the anonymous copy remains on this device. Account stores/queues and active vocabulary selection are separate from sign-in.

iOS sharing accepts text/URL actually supplied by the host, with an explicit Save draft button. It does not fetch page content or infer selected sentences from a URL. App startup/foreground drains the shared inbox into durable pending captures, then acknowledges files. Shared drafts can be chosen/edited/confirmed or dismissed; confirmation preserves an independent source without creating fake history or incrementing forgotten count. Repeated capture/confirmation IDs deduplicate identical requests and reject changed content. App Group failure reports the Paste/JSON fallback. Build and temporary-store tests do not establish actual signed host/device sharing.

The extension's current behavior is unchanged. Count and retained history length remain independent on both surfaces.

Settings offers an explicit HTTPS API address and Sign in with GitHub. The system browser opens only on that user action; callback state/scheme/path/query and the active attempt are validated before exchanging a short code. A successful connection saves credentials in Keychain and the origin in preferences, but leaves anonymous vocabulary/history local. Cancelled sign-in does not exchange/store credentials; Disconnect removes local credentials, attempts server revocation, pauses the old account queue and selects anonymous vocabulary without deleting the account copy.

Open account vocabulary downloads account data while sending stays paused. Ownership preview offers keeping anonymous, migrating the original shared baseline and later intents, copying an unrelated current snapshot, associating history without adding count, replacing cloud fields with an explicit current-version snapshot, or a separate lifecycle with new history IDs. Different sources/deleted lifecycles default to keep anonymous. Changed source/account revisions invalidate publication. Confirmation copies the selected data to the account partition and enables its queue; it does not turn the retained anonymous copy into another sender.

Foreground entry, pending local changes and Synchronize now invoke finite sync batches. A foreground network recovery starts a bounded retry flight; transient failures or remaining work retry after 2/4/8/16/32/60 seconds. Persisted wire deadlines still gate submissions. Backgrounding all vocabulary windows, disabling sync, selecting another vocabulary or changing accounts cancels automatic retries. Exhaustion retains the queue for the next foreground/network/manual trigger. Queued items survive restart with the same frozen ID/body. Context/URL requests default off per device and require account consent as well. Settings has independent source toggles, confirmed historical backfill and confirmed removal of all uploaded contexts/URLs. Changing a preference pauses sync; turning it off retains uploaded fields. Enabling on another device does not authorize this device. Local sources and complete backups remain after cloud removal. Removal freezes a durable request before network I/O; an unknown result blocks sending across restart until the same request is retried. Re-enabling cannot rebase old source requests to the new source revision: they remain conflicts for explicit review. Confirmed historical backfill queues enabled fields for cloud-known events without changing count or review; cancellation retains already queued work. History pages bind the count snapshot's entry version and reconstruct retained order from positions; explicit legacy merges use stable timestamp/position order. Basic conflicts ask before accepting cloud values or copying local data to a separate lifecycle. Account changes dismiss old editors/import/export state and reschedule the selected vocabulary's reminders. Restored server epochs pause sending and preserve local data until explicit recovery review.

Only a service advertising the required history-order/history-version/explicit-lifecycle capabilities can enable this development sync path. Real Swift/URLSession-to-local-Node/SQLite integration now passes with separate synthetic device processes. Hosted OAuth, signed Mac/iPhone synchronization, accessibility and complete release acceptance remain unverified; local HTTP and mocked tests do not prove those behaviors.

The independent ServerSnapshotLoader reads a fixed-boundary, versioned new-epoch snapshot without changing the active vocabulary or resending old queued requests. It rejects account/epoch/preference changes during download and supports cancellation. Review restored cloud vocabulary then offers cloud fields, retained local conflicts, current-version local field restore or a separate lifecycle. Missing words/local tombstones are retained by default; deleted cloud lifecycles cannot be resurrected. Confirmation uses a frozen candidate and a recent online server recheck; old requests remain in its private recovery generation. A failed save, local revision change or another restore blocks publication. Sync stays paused afterward. Current server admission IDs replace old local quota records, without replaying historical answers. See [epoch recovery evidence](verification/2026-10-09-epoch-recovery.md).

Account backup merge first pauses sending and loads current cloud lifecycle/tombstone/history state. Current fields are retained by default; selected fields can come from the backup, history can be associated without adding count, or a separate lifecycle can be created explicitly. Cached/unavailable-cloud previews cannot be confirmed. Pending fields must be synchronized/resolved before replacement; unrelated current queues remain intact. Immutable conflicts and tombstones prevent silent overwrites/resurrection. Publication rechecks relevant cloud versions, account/epoch/preferences and local revision, and remains paused afterward. Later imported history and historical answers do not increment count or replay review intervals/admissions. Whole account replacement stays unavailable. See [account backup evidence](verification/2026-10-09-account-backup.md).

## Connected Chinese translation

Account connection injects an authenticated backend Chinese provider into the
shared lookup actor. It sends only the selected word and `zh-CN`; credentials stay
in Keychain and Hermes keys remain server-side. Cache namespaces include backend
origin and account. Provider changes invalidate old in-flight results; packaged
English lookup remains independent. Connected failures remain explicit and do
not switch to a direct client provider. The backend may return server-side MyMemory fallback; both `hermes` and `mymemory` sources are accepted. Disconnected lookup retains MyMemory. Definitions
accept both `hermes` and historical `mymemory`, with no rewrite of old histories.
The Node/SQLite API and isolated Hermes are deployed on Tencent Lighthouse. Server-local acceptance passed; public access remains blocked pending filing. The new server fallback is locally verified and not yet deployed.

## October 16 completion boundaries

macOS uses a native Settings scene (Command-comma) sharing the same account/repository pool. Dropping one local `.json` file on the vocabulary window opens the extension-snapshot preview; it does not import automatically. Invalid/multiple/remote drops are rejected. Complete backups still use the explicit restore entrypoints.

An online account may claim this device for reminders or release its own selection. The backend derives the device from authentication and compares the observed selection revision. A lost response is reconciled by reading the current account; no automatic reclaim occurs. Local permission and the local reminder toggle remain necessary. Devices cancel account schedules when they learn another device is selected, even if vocabulary sending is paused. Offline devices retain their last known state, so globally immediate deduplication is not promised. Services lacking `reminder-device-v1` cannot schedule account reminders; anonymous reminders remain local. Real notification delivery and signed-device handoff are still unverified.
