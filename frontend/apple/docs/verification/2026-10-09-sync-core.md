# Native sync core verification — 2026-10-09

This checkpoint implements the persistent/native-network portion of Apple stage four. It does **not** complete stage four or enable vocabulary transmission from the normal app. All test vocabulary, identities and credentials are synthetic; no user Keychain items, Chrome storage, production API or live OAuth provider were used.

## Implemented boundaries

- Store V4 adds indexed logical operation sequence fields and generation-scoped sync records. V1/V2/V3 migrations preserve an independent pre-upgrade recovery store. V3 capture drafts and logical ordering were verified through an actual SQLite migration.
- Remote API base state and local mutations remain separate. Pulls retain local edits and private encounter sources. When a remote count might already include a pending encounter, the previous visible projection remains until a durable history scan resolves that ambiguity. Review projections retain the originally calculated schedule; a lost reply does not advance the same answer twice.
- A logical creation/migration/restore/merge can produce several bounded wire requests. Each eligible request is saved before networking; ID and bytes stay identical on retry, including a refreshed session. The operation's privacy selection stays fixed through its history chunks. Same-entry dependencies cannot overtake a backed-off request, while unrelated entries can proceed.
- Conditional successors account for acknowledged duplicate/no-op history requests. They do not raise a user's observed base to overwrite unseen remote changes merely because an additive predecessor succeeded on a newer server version. Such changes remain CAS conflicts.
- Snapshot, delta and history cursors commit with their corresponding state/events. Fixed pull boundaries survive restarting a flight. Partially acknowledged merge/restore fields do not apply a second count change while later history chunks remain pending.
- The authenticated coordinator coalesces concurrent triggers and runs bounded foreground batches: at most five state pages, ten history pages and five submissions, checking a 20-second work deadline between requests. Individual transport deadlines still apply; this is not an exact total wall-clock limit. Pending state/retry metadata survives independently of the coordinator. Disabled sync or a mismatched identity does not read/transmit vocabulary; logout invalidates late replies. Epoch changes suspend sending and preserve pending intents.
- Permanent rejection retains the operation and conflict. Rejected reviews remove their tentative admission/schedule while retaining the event for resolution. Discarding a rejected predecessor makes pending dependents explicit conflicts rather than silently rebasing them. Source association/new-lifecycle resolution is still required when no matching cloud base exists.
- The wire contract adds `legacyMerge` for an explicitly confirmed count delta/current definition, with history imported separately. Swift and TypeScript consume the same request fixture. The Worker rechecks the user epoch inside the atomic write guard; an epoch/preference race does not retain a permanent operation-conflict receipt.

## Remaining acceptance

Account ownership preview and partition selection, application lifecycle/changes triggering sync, status/conflict UI, source association/enrichment, retained history/source ordering, online account-backup restoration and explicit epoch reconciliation remain implementation work. The normal Settings sign-in still does not invoke the sync coordinator or upload anonymous vocabulary.

The coordinator tests exercise `NativeSyncAPI` and `AuthenticatedAPIClient` with a synthetic transport. Backend tests independently exercise real local Worker/D1 behavior. These are not evidence of a Swift-to-Worker end-to-end session or hosted two-device synchronization. Real OAuth configuration/deployment, signed Mac/iPhone sessions, Share Extension delivery, system notification behavior, large-history sync performance and actual accessibility/device acceptance remain unverified.

The full Apple implementation goal remains active. The next integration must preserve explicit ownership confirmation and the plan's account/epoch recovery gates.
