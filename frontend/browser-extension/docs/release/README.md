## Reproduce the packages

From `frontend/browser-extension/`, use Node 22.22.3 from `.nvmrc`:

```sh
nvm install
nvm use
npm ci
npm test
npm run compile
npm run zip
npm run zip:firefox
```

Each zip command builds its browser target before archiving. Review the generated manifests and ZIP contents. Chrome output is `.output/remember-me-0.1.0-chrome.zip`; Firefox output is `.output/remember-me-0.1.0-firefox.zip`, with a source archive generated by WXT. Only the Chrome ZIP is intended for the first store submission. Do not upload the repository, development output, or `.output/chrome-mv3-feedback/`.

For future releases, use `npm version <version> --no-git-tag-version` to keep package metadata and the lockfile aligned, rerun the release checks, update the release notes, and upload to the same store item.

## Optional installed-browser smoke check

The standalone smoke script below targets the earlier open-shadow card and Remember/Forget controls. It requires adaptation for the closed-shadow bookmark counter before it can validate the current release; it was not executed for the encounter-counter change. Use the current automated checks and [record verification](../verification/2026-09-30-encounter-counter.md) as the evidence for that feature. Do not reopen the shadow root just to satisfy an old test selector.

[scripts/release-smoke.cjs](../../scripts/release-smoke.cjs) loads the production Chrome build in a fresh temporary Chrome for Testing profile, serves a loopback example page, blocks the external dictionary and requires packaged WordNet definitions, then exercises selection/save/reset/delete/export/import through the actual extension. It closes the browser and removes that temporary profile when finished. It never attaches to an existing profile. It also regenerates the store screenshot and a separate [400 × 600 popup verification image](assets/popup-verification.png); the latter is not a store-sized screenshot. The offline-dictionary revision of this optional script has not yet been run; earlier release records describe its older online-fixture version.

This optional script needs an existing Playwright installation with its Chromium browser; Playwright is not added to the extension's dependencies or normal test suite. Set `REMEMBERME_PLAYWRIGHT_PATH` to that installation's absolute package directory (or leave unset if `require('playwright')` resolves), then run:

```sh
node scripts/release-smoke.cjs
```

Run it after `npm run zip` or `npm run build`. It checks the initial 0.1.0 manifest version; update that assertion for future release candidates. Successful fixture lookups do not prove live dictionary availability, native context-menu behavior, or a browser-toolbar popup opening correctly.

## Before submission

- Supply the publisher name, public support contact, and an accessible HTTPS privacy policy URL. Replace draft placeholders and date the policy when published.
- Review prepared listing copy and privacy declarations against the actual submitted package. Decide distribution visibility in the dashboard; Unlisted is suitable for a link-based pilot but still requires review.
- Review icon, promotional tile and actual extension screenshots. Use only disposable example words, contexts and URLs.
- Verify the new identity/alarms permissions, IndexedDB upgrade retention, registered OAuth callbacks, live Hermes, account sync/privacy and recovery-copy behavior. The current materials are unpublished drafts; backend service retention must be specified before submission.
- Complete and record the remaining installed-browser cases in [testing.md](../testing.md), especially native context menus, live dictionary connectivity, update behavior, and file access if advertised. Mocked APIs or intercepted dictionary fixtures are not live service verification.
- Register the developer account and complete its account requirements. Upload the ZIP, fill listing/privacy/distribution/test instructions, and submit for review.

Prepared files do not automatically publish anything or create an account. The owner must review data-use certifications and supply public contact details before submission.

## Firefox status

The project can build Firefox MV2 packages. It is not yet presented as AMO-ready: choose a stable Gecko add-on ID, configure accurate data-transmission declarations/consent and supported Firefox versions, and test the installed add-on. A dictionary lookup transmits the selected word, so declaring `required: ["none"]` would be inaccurate. Mozilla's built-in consent is available from desktop Firefox 140; older versions require another compliant approach. These Firefox-specific product/configuration choices are left for a dedicated Firefox release, not silently claimed complete by a successful build.

Supply source code and exact build instructions for Mozilla review. Inspect WXT's source archive before uploading it: it must contain source and the lockfile, and must exclude credentials, local feedback logs and private artifacts. AMO review/signing is an external step.

For the source archive, extract into an empty directory, use Node 22.22.3, run `npm ci`, then `npm run build:firefox`. WXT's default source ZIP excludes test files; run the automated suite from the full checkout, not that review archive.

## Data migration

The Local feedback build and store installation have separate extension identities/storage. Export once from the old installation, import once into the new installation, and verify counts and histories before retiring the old copy. Do not repeatedly import the same backup. Never overwrite browser profile files. Backups include full URLs and contexts.

## 0.1.0 release notes

- Look up individual English words on supported webpages.
- Save words with forget counts, definitions, sentence contexts, full source URLs and encounter timestamps.
- Review, sort, reset counts, confirm deletion, and import/export JSON vocabulary.
- Use the Remember Me selection context-menu shortcut.
- Use a consistent Remember Me popup title and extension icon; omit the unused `activeTab` permission.
