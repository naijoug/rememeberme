# 2026-10-09 unified API foundation

Implemented a separate local backend package for the Apple plan's unified API dependency. Root npm workspaces/website/extension-sync work is deferred explicitly; extension dependency files and runtime storage were not migrated.

## Executed evidence

- Current official Workers/D1/GitHub OAuth references and published package metadata were checked. D1 uses prepared bindings, transaction batches and conditional CHECK guards. Worker bindings/runtime types were generated by patched Wrangler 4.149.0; Node 22.22.3 matches package requirements.
- 22 integration/contract cases passed across five test files in local workerd/D1: repeat/concurrent operation replies, distinct encounters, user isolation, real SQL-trigger rollback, reset/history, tombstones, shared baseline/import behavior, large count precision refusal, privacy options, fixed boundary/epoch pulls, OAuth browser/provider/native challenge binding, concurrent single-use code exchange, refresh/revocation/erasure, expired codes, rejected identity replay, rate bounds, snapshot/review/restore and shared fixtures.
- TypeScript typecheck passed. Wrangler **dry-run** bundling passed; no Worker/D1 resource was registered or deployed.
- D1 migration applied to `/tmp/rememberme-api-local-smoke`. One loopback-only server was launched and checked: health 200 JSON, unauthenticated unknown API 401 JSON, missing auth route 404 JSON, root 200 HTML. It was stopped after the smoke test. This did not use user tokens or real vocabulary.
- Swift added independent wire DTOs and consumed the same request/result/error fixtures; the 52-test core run passed at that checkpoint. Native Keychain, authentication session UI, transport/outbox/checkpoint/overlay/account ownership integration are not yet implemented.

All provider requests in tests are intercepted with the current `@msw/cloudflare`/MSW integration and a catch-all network-error handler. Synthetic account/token data is stored only in resettable test bindings. The old `fetchMock` API was unavailable in the current plugin; tests were corrected to current APIs. A real Worker-runtime test also found unsupported `redirect:"error"`; provider fetch now uses manual redirects and status checks. Failed bootstrap/test attempts are not counted as acceptance.

## Toolchain and limits

The npm 10.9.8 peer resolver reproducibly crashed (`edgesOut`). An isolated npm 11.21.0 process installed the scoped backend package; global npm/extension dependencies were preserved. Initial latest-tag toolchain packages had four high dev-tool advisories; explicit available patches (Wrangler 4.149.0 / plugin 1.4.0) resolved them, with zero reported vulnerabilities after the update. Official esbuild/workerd installation checks were run. This is dependency evidence, not a claim of a security audit.

Config/body bounds: 256 KiB streamed JSON, one operation/request, event chunk 25, state page 50, history page 25; new token integers are JS-safe, old count/time doubles remain compatible. Rate bindings are configured for login/API requests, while globally atomic review admissions use D1. Hosted CPU/row usage and multi-region rate behavior are unmeasured.

Required-secret warnings reflect intentionally absent real GitHub configuration; synthetic test bindings are used only during tests. No live OAuth login, real-device native session, Keychain access or hosted sync occurred. Cloudflare credentials, chosen domains/D1 bindings, remote migration/deploy/restore procedures and native client integration remain pending. Remote CI configuration exists but has not been observed running.
