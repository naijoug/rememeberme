# Remember Me Cloudflare 实施计划

日期：2026-09-30，更新：2026-10-09。状态：原生依赖的本地 API 已开始实施；网站、扩展迁移和部署仍待实施。

目标是将旧 English 网站的词条融入 Remember Me，形成扩展采集、云端存储与同步、网站整理与复习、浏览器提醒的闭环。采用 TypeScript、Hono、Cloudflare Workers、D1 和 Workers Static Assets，优先在免费额度内运行。

本文描述目标方案与实施顺序，不代表后端功能已实现或验收已通过。扩展在 `frontend/browser-extension/` 独立运行，词库仍存于扩展本地；Apple 客户端已建立独立本地工程与共享核心，完整功能仍在开发。`backend/` 已有独立包、本地 Hono/Workers/D1 API、原生 OAuth 兑换、条件操作/增量/复习和隔离测试；未部署或接入真实词库，各端尚无运行中的云同步。实际范围见[后端验证记录](../backend/docs/verification/2026-10-09-api-foundation.md)。

当前已实现的目录、运行时与数据流见[项目架构总览](architecture.md)；下文的目标目录和云端组件属于待实施方案。

[macOS 和 iOS 前端实施计划](apple-clients-implementation-plan.md)补充原生客户端、本地存储和统一 API 的接入方式。原生本地版本可先独立交付；跨设备同步依赖本计划中的认证/API，扩展自动同步另需完成扩展迁移阶段。后端同时面向网站、扩展与原生客户端定义语言无关契约。

2026-10-08 契约补充：共同数据规范采用 Apple 计划中的[数值、时间和格式契约](apple-clients-implementation-plan.md#数值时间和格式契约)、[共同来源迁移](apple-clients-implementation-plan.md#首次迁移与跨设备共同来源)、[备份恢复规则](apple-clients-implementation-plan.md#新版备份恢复与删除冲突)和 review-v1。下文阶段零/一落实共同 schema 与 fixtures，阶段二增加原生登录兑换、迁移基线与恢复快照接口；这些仍是待实施约束，不是后端已支持的能力。

## 实施范围与默认选择

| 项目 | 首版范围 |
| --- | --- |
| 使用范围 | 先满足个人使用，所有服务端数据按用户隔离 |
| 网站 | Vue 3 + Vite，词库、详情、手工添加、导入、今日复习、设置 |
| 后端 | Hono Worker，通过 D1 binding 访问数据库 |
| 部署 | 同一 Worker 提供 `/api/*` 和网站静态资源，开发、预发布、生产数据分开 |
| 登录 | 暂定 GitHub OAuth；在后端阶段确定账号与回调配置 |
| 扩展 | 保留现有单词采集，新增本地事务存储、账号连接、同步和复习提醒 |
| 提醒 | 用户主动开启的浏览器每日汇总通知，另有网站内待复习入口 |
| 网站离线能力 | 首版在线读写；扩展继续支持离线采集 |
| 后续范围 | 邮件提醒、网站离线编辑、扩展短语查词、高级记忆算法 |

个人使用、登录方式和提醒渠道是实施默认值，不是已经确认的产品偏好。若改为邮件优先，在提醒阶段增加发信服务与额度评估；浏览器关闭期间的触达不能由扩展通知保证。

## 数据与同步契约

| 数据 | 责任与关键字段 |
| --- | --- |
| users、sessions、devices | 登录身份、网站会话、扩展设备连接与撤销 |
| vocabulary_entries | 用户、稳定 ID、展示文本、规范化文本、类型、独立遗忘计数、笔记、版本、删除状态 |
| entry_definitions | 中文或英文释义、词性、英美音标、来源；独立于采集历史 |
| encounters | 稳定事件 ID、采集时间、上下文、URL、当时的释义快照 |
| review_states、review_events | 到期时间、间隔、复习版本与结果记录 |
| user_preferences | IANA 时区、提醒时间、每日新增上限、隐私选项 |
| import_batches、import_items | 导入来源、内容摘要、逐项处理结果和重试进度 |
| sync_operations、sync_changes | 操作 ID、请求摘要、已提交结果与服务器增量游标 |

词条类型支持 `word / phrase / abbreviation / proper_noun`。规范化按类型定义，缩写保留展开形式，词形关联不自动合并现有不同拼写的计数。旧站缺失的采集时间、历史和次数保持未知；导入时间另记。手工词条遗忘次数未记录时显示“未记录”，第一次实际采集才开始计数。

为词条检索、用户与规范化文本、复习到期查询、事件去重、用户与增量游标建立索引。列表采用游标分页，详情的历史另行分页，避免每次请求扫描和返回整个词库。

### 操作处理规则

1. 采集在扩展后台完成本地事务：同时保存词条变化和待同步操作，持久化成功后才向页面确认。
2. 每次变更具有稳定 `operationId`。服务端以用户和操作 ID 去重；同 ID 不同请求内容返回冲突；重复提交返回已提交结果。
3. D1 中的去重记录、业务更新、增量记录一起提交。计数变化由条件 SQL 和原子批次保证；不能“忽略重复插入后仍无条件自增”。D1 的 `batch()` 提供批次回滚能力，但不等同于任意跨请求事务，见 [D1 Database](https://developers.cloudflare.com/d1/worker-api/d1-database/)。
4. 采集事件按 ID 合并；编辑、重置计数和复习状态使用版本检查。已知拒绝的操作进入冲突状态，不无限重试。
5. 并发复习同一词条时，只接受符合当前复习版本的状态更新；冲突后刷新词条，不让重复点击或另一设备再次推进间隔。
6. 删除保留墓碑并拒绝旧操作复活词条；显式重新添加使用新的生命周期或 ID。首版保留墓碑，后续清理必须有过期游标和全量恢复协议。
7. 增量以服务端递增序号排序，不使用设备时间戳作为唯一排序依据。推送逐项返回成功、冲突或错误；重试只重发未确认操作。
8. 首次同步分批拉取快照并固定快照边界，再拉取后续增量。应用增量时保留未确认的本地操作，不覆盖离线采集。
9. 相同旧文件在不同客户端生成共同来源 ID；基线 count 和历史只应用一次，历史导入不再自增。普通采集、基线、补充来源字段和恢复快照是不同操作；同规范化键不同来源先返回可处理的冲突，不自动累加。count 以可空有限非负数表示，区分未记录与零，旧小数/大数不截断；条件写入检查溢出及加一无变化。
10. 恢复保留事件身份，但不使用备份版本覆盖当前版本、不重放历史推进复习、不复活墓碑。账号恢复在线取得当前版本，显式选择的快照字段走条件提交；缺失条目不代表删除。默认保留当前，账号整库替换不属于首版。

服务器提交后确认结果；网络断开不等于未提交，使用相同操作 ID 查询或重试。页面消息失败时仍禁止回退到页面直接写存储，保持现有后台所有权。

### 备份与导入兼容

- 保持旧 JSON 校验与显式“合并导入”的累加语义。同步、首次迁移和新版恢复使用独立入口，不偷偷修改旧导入行为。
- 首次迁移使用稳定批次和条目 ID；重复执行不重复增加计数或历史。迁移过程中可断点续传，报告区分新增、已有、失败和待处理。
- 新完整备份使用版本封装，包含词条、独立释义、笔记、复习和来源；恢复保留 ID。凭证、会话和待同步网络请求不导出。
- 继续提供旧格式兼容导出。原有词条字段保持完整；新类型、未知计数和独立释义的降级规则先用样例明确，界面说明损失。不得为兼容导出伪造真实采集历史。
- 本地迁移校验通过前保留原数据。切换后原 `local:words` 作为只读备份，禁止两个存储同时作为写入源；回退前先导出切换后的新增操作。

### 阶段二 实现认证和 D1 API

- [ ] 建立 schema migrations、索引、词库 CRUD、采集、导入批次、同步推送与拉取接口。
- [ ] 暂按 GitHub OAuth 网站登录实施，使用 state 和适用的 PKCE 保护，网站会话使用 HttpOnly、Secure cookie；更新请求验证来源并处理 CSRF。见 [GitHub OAuth 文档](https://docs.github.com/en/apps/oauth-apps/building-oauth-apps/authorizing-oauth-apps)。
- [ ] 扩展在已登录网站确认连接，通过短期、一次性、绑定设备挑战的交换流程取得独立设备凭证；凭证只由后台持有，支持过期与撤销。
- [ ] 所有 API 从已验证会话解析用户，禁止客户端自行指定数据所有者；为请求大小、批次数量与登录尝试设限。
- [ ] 通过 D1 binding 和参数化 SQL 访问数据；采用具名 SQL migrations，首版不要求增加 ORM。
- [ ] 写操作持久化完成后才返回成功，日志记录请求 ID、操作 ID 和结果，不记录凭证、上下文正文或完整 URL。

验收：两个测试账号无法互读互改；重复操作、并发保存、撤销凭证、事务失败和 API 错误状态通过本地 Worker 集成测试。

- [ ] 旧词条分日进入学习队列，导入不会让所有词条当天同时到期；复习状态与采集遗忘计数分别更新。
- [ ] 实现扩展 alarms 调度与 notifications 通知，用户主动开启；保存 IANA 时区和当地提醒时间，启动检查调度，处理休眠、跨日与夏令时。
- [ ] 每个账号与设备按当地日期持久化提醒去重；已有到期词条才提醒，完成后跳过，支持暂停和稍后提醒。多设备连接时首版由用户选择一个提醒设备。
- [ ] 通知点击打开今日复习；工具栏错误、保存结果和待复习数有明确优先级，互不静默覆盖。

验收：相同复习提交不会重复推进间隔；到期边界与时区正确；提醒开关、暂停、重启、休眠和通知点击经过实际浏览器验证。权限拒绝时保留网站与扩展内待复习入口。参考 [Alarms](https://developer.chrome.com/docs/extensions/reference/api/alarms) 与 [Notifications](https://developer.chrome.com/docs/extensions/reference/api/notifications)。

里程碑三：每日复习与主动提醒可用。

### 阶段六 预发布与正式部署

- [ ] 确认 Cloudflare 账号、部署身份、OAuth 配置与域名选择；使用默认平台域名也可开始验证。
- [ ] 建立预发布和生产的独立 Worker、D1 与秘密配置，构建网站后与后端一起发布；迁移在受控部署步骤执行。
- [ ] 采用索引、分页、有限同步批次与本地 Markdown 转换，测量 CPU、D1 行读写和真实请求结果，不以数据量小替代测量。
- [ ] 用测试账号和词库在预发布验证登录、同步、导入、复习和提醒；CI 保持使用本地隔离数据。
- [ ] 提供 D1 导出、完整用户备份、迁移前恢复点和恢复流程，在测试环境演练；恢复前暂停同步，恢复后通过新的同步 epoch 让设备全量对齐，避免旧游标掩盖变化。
- [ ] 区分代码回滚与数据库恢复，数据库采用向后兼容的分步迁移；旧版本回滚不能丢弃已经产生的新数据。
- [ ] 更新行为、架构、测试、隐私、扩展权限与安装发布文档，记录实际浏览器结果和未执行项。

验收：预发布完整流程通过、迁移及恢复演练可追溯、日志与额度可查看，然后执行已授权的正式发布。正式导入真实词库与恢复覆盖数据是明确的用户数据操作，单独记录执行结果。

## 免费额度与实现约束

以下是 2026-09-30 核对的额度，部署时再次核对。个人词库预计可以在免费额度内运行，这是待上线测量的估计。

| 服务 | 当前免费额度 | 实现影响 |
| --- | --- | --- |
| Workers | 每天 10 万次请求；HTTP 和 Cron 每次 10ms CPU | 小批次处理；CPU 时间不包含网络和数据库等待 |
| Static Assets | 静态资源请求免费且不限次数 | 静态页面直接走资产服务；API 路由才进入业务 Worker |
| D1 | 每天读 500 万行、写 10 万行 | 建索引和分页；指标是行数，不是 SQL 请求数 |
| D1 存储与调用 | 账户 5GB，单库 500MB；每次 Worker 调用最多 50 个 D1 查询 | 批量导入同时控制 SQL 数量、请求大小和 CPU |
| D1 恢复 | 免费计划 Time Travel 保留 7 天 | 另外提供完整导出，避免将短期恢复当成长期备份 |

来源：[Workers 定价](https://developers.cloudflare.com/workers/platform/pricing/)、[Workers 限制](https://developers.cloudflare.com/workers/platform/limits/)、[静态资源计费](https://developers.cloudflare.com/workers/static-assets/billing-and-limitations/)、[D1 定价](https://developers.cloudflare.com/d1/platform/pricing/)、[D1 限制](https://developers.cloudflare.com/d1/platform/limits/)、[Time Travel](https://developers.cloudflare.com/d1/reference/time-travel/)。

超出免费配额时 API 可能不可用，扩展保留本地采集并显示同步失败；升级付费计划是后续用量决定。域名购买和邮件发送的费用或额度单独评估。首版按请求计算到期词条，浏览器调度提醒，不要求云端 Cron；需要服务端触达时再增加 [Cron Triggers](https://developers.cloudflare.com/workers/configuration/cron-triggers/) 和实际发送渠道。

## 验证与完成标准

后端使用 Cloudflare 的 [Vitest 集成](https://developers.cloudflare.com/workers/testing/vitest-integration/) 在 Workers 运行时验证 D1 和 API；领域逻辑使用纯单元测试；网站验证主要用户流程；扩展按现有验证指南扩大存储、消息和采集回归。新实现遵循 [Workers Best Practices](https://developers.cloudflare.com/workers/best-practices/workers-best-practices/)，采用 binding、生成的环境类型、受控秘密配置与结构化日志。

每阶段只在实施和实际验证后标记完成。共享契约变化需要覆盖相关应用；浏览器权限、后台生命周期和通知需要实际安装扩展验证，不能用模拟测试或构建成功替代。

本计划的最终完成标准是：旧内容可核对地迁入，现有备份可用，扩展离线采集不丢失，同步重复请求不重复计数，网站可整理与复习，开启提醒后实际触达，服务运行在 Cloudflare，备份恢复可演练，当前文档与已实现行为一致。

## 启动前需要确定的信息

- Cloudflare 账号和部署权限；OAuth 应用及回调配置可在本地实现期间准备。
- 首版是否接受 GitHub 登录；默认以个人使用为先，并保留用户隔离。
- 是否接受浏览器提醒为首版渠道，以及提醒时间、时区和每日新增数量。
- 上下文和 URL 的云端同步范围；默认不上传，用户设置后才启用。

这些信息影响相应阶段，可以先完成本地模型、迁移工具、测试和网站开发，不需要提前创建云资源或部署。当前步骤仅制定计划。
